## 2. P0 —— 演示当场翻车

### P0-1 小程序详情页 SKU 规格区渲染与点选失效
- **位置**:`miniprogram/pages/detail/detail.wxml:25-28`(联动 `detail.js:47-49、70-71、93-95`)
- **现象**:`wx:for="{{detail.skus}}"` 漏写 `wx:for-item="s"`,循环变量是默认的 `item`,所有 `s.*` 引用为空:
  - 多规格商品(演示库商品 1 有"中号/大号"两 SKU)规格 chips 渲染成**空白块**;
  - 点击 chip 时 `data-id="{{s.id}}"` = undefined → `pickSku` 置 `Number(undefined)=NaN`;
  - 此后「加入购物车/立即购买」守卫 `!this.data.buy.skuId`(NaN falsy)永远弹「请先选择规格」——一次点选即报废,须重进页面。
- **期望**:补 `wx:for-item="s"`(同项目 mine.wxml 用 `it` 的约定)。
- **证据**:
  ```html
  <view class="sku {{buy.skuId === s.id ? 'on' : ''}}" wx:for="{{detail.skus}}" wx:key="id"
    bindtap="pickSku" data-id="{{s.id}}">
  ```
- 缓解因素:detail.js 会预置 `buy.skuId=skus[0].id`,不点规格直接购买可走通,故未在静态阶段判 P0;但"演示选规格"一碰必现,人工复验后定为 P0。

### P0-3 admin 详情接口与 SKU/图片弹窗、查看弹窗字段契约错配
- **位置**:后端 `service/product.ts:125-142`(detailWithChildren);前端 `sku-edit.vue:143-152`、`views/product.vue` 查看弹窗(约 299-303、40-62)
- **现象**:detailWithChildren 直接 spread TypeORM 实体 → `skus[]` 键为 **camelCase**(`skuName/attrs/status`),`images[]` 为**对象数组** `{id,productId,url,sort,…}`;而弹窗按 app 端契约解析 `s.sku_name`(undefined → SKU 行全空、属性全丢),`images` 直接塞进字符串输入框(v-model 绑对象、缩略图破图);此时点保存 `images.filter(u => u && u.trim())` 对对象调 `.trim()` → **TypeError 静默失败**(在 try/finally 之前抛出,无提示)。连带:product.vue「查看」弹窗读 `category_name/market_price/craft_intro/rating`,这些键只存在于 app 端 appDetail,detailWithChildren 没有 → 分类/市场价/工艺恒「-」、评分恒 0。
- **期望**:detailWithChildren 输出与 appDetail 统一(snake_case + `images:[url,…]`),或前端按实体键解析。
- **背景**:框架 page/list 走原生 SQL 返回列名(snake),info/find 走实体序列化返回属性名(camel)——"字段命名双轨差异"是全模块契约易错点,此处从引入起即错配。

## 7. 勘误(对初版静态审查的三处修正)

1. 并发"重复支付双倍销量/取消双倍回补"的判断过强:在 MySQL 默认 RR 隔离 + 绝对值写语义下,**同单**重复请求实测只计一次;**真实风险是守卫穿透(两次都成功)+ 跨单丢更新**。修复建议(条件更新/SQL 自增)不变,且必要性更高。
2. 浏览链路审查曾断言 `detail?id=abc`"不 500、同文案兜底"——实测为原生 SQL 错误 `Unknown column 'NaN'` 直出,列为 P2。
3. 管理端审查对 P0-2 的机制描述(空 SET → TypeORM UpdateValuesMissingError)不成立:saveProduct 为 merchantId 兜底使 SET 非空;**真实拦截点是第 65 行无条件 title/price 必填校验**。
